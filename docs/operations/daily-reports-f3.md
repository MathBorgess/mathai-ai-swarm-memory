# Daily reports — F3 (servidor)

F3 serves the morning HTML on the phone and receives the evening. It stores each
submission as an immutable numbered revision and hands the night session a durable job.
It does not run the night session: that is F4. Until F4 exists the jobs sit in the outbox
where you can see them, which is the point.

## What it exposes

| Route | Method | Purpose |
|---|---|---|
| `/YYYY-MM-DD.html` | GET, HEAD | the report generated by `report morning` for that date |
| `/evening` | POST | the `EveningPayload` from the page's **Enviar** button |
| `/evening/revision?day=YYYY-MM-DD` | GET | latest saved revision, for the page's restore |
| `/healthz` | GET | loopback only, no auth, for the tunnel probe |

Nothing else. There is no route that lists a directory, no route that reads outside
`output_dir`, and no `Access-Control-Allow-*` header anywhere: the page is same-origin by
construction, so CORS would only exist to let another site read the vault.

## Auth profiles

`server.auth_mode` is required. There is no default that could become a public vault by
omission, and `build_server` refuses a config with no `server` block at all.

| Profile | What it asserts | May bind |
|---|---|---|
| `cloudflare-access-jwt` | every request carries a JWT whose RS256 signature, `iss`, `aud`, `exp` and email are verified | any address |
| `tunnel-loopback` | only `cloudflared` reaches the socket; Access is enforced at the edge | loopback only |
| `synthetic-local` | nothing at all; development and tests | loopback only, and `public_origin` must also be loopback |

`ServerConfig.check_bind_gate()` runs on load, on construction and on every `--host`
override, so "I forgot to put Access in front" is a startup error rather than a published
vault. `cloudflare-access-jwt` without a complete `server.access` block is refused too.

`Cf-Access-Authenticated-User-Email` is **never read**. Anyone who can reach the socket
can set it. The only thing that establishes the owner is the signature over the token,
checked against `certs_url`, which must be HTTPS on the configured `team_domain` — a JWKS
on another host would let whoever controls it mint owners.

### Config

```json
{
  "public_origin": "https://reports.mathai.com.br",
  "server": {
    "bind_host": "127.0.0.1",
    "port": 8787,
    "auth_mode": "tunnel-loopback",
    "max_body_bytes": 262144,
    "request_timeout_seconds": 10,
    "dispatch_command": ["/abs/evening-handler"],
    "dispatch_timeout_seconds": 900,
    "max_attempts": 5
  }
}
```

With Access verified in-process instead of at the edge:

```json
{
  "server": {
    "bind_host": "0.0.0.0",
    "port": 8787,
    "auth_mode": "cloudflare-access-jwt",
    "access": {
      "team_domain": "mathai.cloudflareaccess.com",
      "audience": "<AUD tag from the Access application>",
      "allowed_emails": ["owner@mathai.com.br"],
      "leeway_seconds": 60
    }
  }
}
```

`certs_url` defaults to `https://<team_domain>/cdn-cgi/access/certs`. The AUD tag is not a
secret but it is not a password either: it is what stops a token minted for another Access
application from working here.

## Run it

```bash
mathai-swarm report serve --config /abs/reports.json
mathai-swarm report serve --config /abs/reports.json --host 127.0.0.1 --port 8787
```

`--host` and `--port` override the config and are still gated. The recommended VPS shape
is the named tunnel to `127.0.0.1:8787` with the Access policy on the hostname, which is
`tunnel-loopback`.

## POST /evening

The body is exactly the F2 `EveningPayload` (see `daily-reports-f2.md`). The server:

1. requires `Content-Type: application/json` (`415` otherwise) and a `Content-Length`
   inside `max_body_bytes` — a chunked body has no declared length, so it is `411` rather
   than something the limit cannot cover, and an oversized one is `413` before a byte of
   it is read;
2. requires `Origin` to equal `public_origin` on every mutation (`403` for a foreign
   origin, `null`, or a missing header). Reads do not require it;
3. parses the payload strictly (`400 schema_invalid`, with the offending field named in
   the server log and never in the response);
4. checks `owner_id` against the config, that the day has a morning freeze, and that every
   `task_id` is inside that freeze (`400 owner_mismatch` / `day_not_frozen` /
   `unknown_task_ids`);
5. saves the revision, enqueues the outbox job, then answers.

Error bodies are `{"error": "<stable code>"}`. No traceback, no module path, no echo of
the submitted value — an evening carries the owner's private notes, and a validation
error must not turn them into a log line or a response body.

```json
{"day": "2026-09-14", "revision": 2, "changed": true, "status": "pending"}
```

`changed: false` with `status: "unchanged"` means the content was identical to the latest
revision. Tapping **Enviar** twice is free.

## Revisions

```
<state_dir>/evening/<day>/index.json          latest + history, written last
<state_dir>/evening/<day>/revisions/0001.json immutable
<state_dir>/evening/<day>/.lock               flock, one writer per day
```

Files are `0600`, written to a temp file and `os.replace`d, so a reader never sees a
partial revision.

- The dedup comparison is over canonical content JSON with transport fields excluded, so
  a resend that differs only by `client_saved_at` is not a revision.
- It compares against the **latest** revision only. Editing A → B → A is a real change of
  mind about the day and the night has to see it; hashing against the whole history would
  swallow that third submission.
- Order inside the day lock is revision file, then job, then index. Every crash point
  converges: the index is what makes a revision visible, so a retry after a crash rewrites
  the same revision number with the same content and the same single job.

Read one back:

```bash
python3 - <<'PY'
from datetime import date
from pathlib import Path
from swarm_reports.server.revisions import RevisionStore
store = RevisionStore(Path("/var/mathai/reports-state"))
print(store.latest(date(2026, 9, 14)).content)
PY
```

## Outbox

```
<state_dir>/outbox/pending/<day>-<rev>.json
<state_dir>/outbox/claimed/…   in flight
<state_dir>/outbox/done/…      completion marker, keyed by (day, revision)
<state_dir>/outbox/failed/…    parked after max_attempts, never deleted
```

The HTTP handler never runs the night session. It writes the job inside the same lock that
created the revision and answers `200`, so the owner's phone is told "saved" even when the
handler is broken, restarting, or absent because F4 does not exist. A single background
thread drains the outbox, one job at a time.

Claiming is `os.rename` from `pending/` to `claimed/`, which is atomic on POSIX: exactly
one claimer wins and the rest get `FileNotFoundError`. Completion is a marker keyed by
`(day, revision)` and is checked before dispatch, so a retry cannot repeat an effect that
already landed. `dispatch_command` is an argv list run with no shell and a hard timeout.

### The handler contract F4 implements

`dispatch_command` is an argv list. The job arrives as one JSON object on **stdin**:

```json
{"day": "2026-09-14", "revision": 2, "content_hash": "…", "enqueued_at": "…",
 "attempts": 0, "last_error": null}
```

Exit `0` means the effect landed and the job is marked done. Any non-zero exit, crash or
timeout is a retry, up to `max_attempts`, after which the job is parked in `failed/`.
Because the completion marker is keyed by `(day, revision)`, the handler only has to be
idempotent for a *repeat of the same revision* — which it will see after a crash between
its own effect and its exit.

The job carries no payload. The handler reads the content it names:

```python
from swarm_reports.server.revisions import RevisionStore
revision = RevisionStore(state_dir).read_revision(job["day"], job["revision"])
assert revision.content_hash == job["content_hash"]
payload = revision.payload()   # validated EveningPayload
```

In-process, F4 can pass any `Callable[[OutboxJob], None]` as `ReportServer(dispatcher=...)`
instead of shelling out. Raising `PendingDispatch` means "not wired yet" and leaves the job
pending without burning the retry budget on a real failure.

Without `dispatch_command` the jobs stay pending and visible — the honest state before F4:

```bash
mathai-swarm report serve --config /abs/reports.json --drain-outbox
# pending 2026-09-14 revision 1 attempts 0
# 1 pending; no evening handler configured (F4)
```

`--drain-outbox` never opens a socket. Run it after a crash, or to process what piled up
while the handler was down.

## When the server is unreachable

The page's **Copiar prompt** button puts the same body on the clipboard, and:

```bash
mathai-swarm report evening --config /abs/reports.json --input /abs/evening.json
# revision 1 (new)
```

This is the same function the HTTP route calls — not a parallel implementation — so the
fallback the owner uses on the day the VPS is down produces byte-identical state. A test
asserts the stored content and hash from both paths are equal.

python3 -c "

`synthetic-local` binds loopback only and its `public_origin` must be loopback too, so
this profile cannot be the one accidentally left running on a public address. Submitting
from this page returns `400 day_not_frozen` until a real `report morning` freezes the day.

## Hardening

- The static route is one regex for a literal `YYYY-MM-DD.html`. There is no path to
  join, so `../`, `%2e%2e%2f`, `....//` and every other spelling fail on the route rather
  than on a sanitizer someone has to keep correct. The resolved file must still be inside
  `output_dir`, which catches a symlink planted there, and a symlink is refused outright.
- Responses carry `Cache-Control: private, no-store, max-age=0` (the report renders the
  private vault and must not sit in a phone's cache), `X-Content-Type-Options: nosniff`,
  `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, a `Permissions-Policy` and HSTS
  when `public_origin` is HTTPS.
- CSP is `default-src 'none'` with inline style and script allowed and `connect-src
  'self'`. The page has no external asset and talks to nothing but its own origin.
- Per-connection socket timeout from `request_timeout_seconds`, so a client that opens a
  socket and stalls cannot hold a worker thread.
- `state_dir`, the vault and the environment are not reachable through any route.

## Tests

```bash
cd src/reports && python -m pytest -q
```

- `tests/test_server_http.py` — routing, traversal and encoded traversal, symlink escape,
  headers, origin checks, content-type, length and size limits, error shapes.
- `tests/test_server_auth.py` — real RS256 verification with a keypair generated in the
  test, forged and unsigned tokens, every claim, and the bind gate.
- `tests/test_evening_revisions.py` — dedup, A → B → A, immutability, concurrency.
- `tests/test_cli_serve.py` — the `--input` and `--drain-outbox` seams, and the parity
  assertion between POST and `--input`.
- `tests/test_server_end_to_end.py` — reads the endpoints out of the served page and calls
  them, which is what catches a page whose `fetch` targets a route the server lacks.
